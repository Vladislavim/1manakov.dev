# SEO Factory

Русский язык, Россия (регион 225). Публикации: `/guides`; `/journal` перенаправляет на `/guides`. Основной домен задаётся `NEXT_PUBLIC_SITE_URL`, по умолчанию `https://1manakov.dev`.

## Текущий выпуск

20 оригинальных материалов, из них 5 эталонных: сравнение, инструкция, чек-лист, примеры и решение проблемы с интерактивной формой. Источники, границы рекомендаций, данные спроса и конкретные CTA сохранены для каждой страницы. Все 20 прошли редакционный quality gate. Это разрешение индексации в репозитории, не подтверждение размещения или индексации поисковиками.

7799 исходных строк Wordstat → 7717 нормализованных запросов → 2972 кандидата → 190 предварительных кластеров. Для 140 актуальных кандидатов есть SERP-проверка, 76 имеют высокий эвристический балл. Полный отчёт: `seo/reports/SEO-REPORT.md`, включая top 100. Суммировать частотности как уникальный спрос нельзя.

Кластеризация лексическая с тематическими правилами, не embedding-модель. Сохранены 20 целевых выдач и 40 структурных HTML-образцов конкурентов. Наличие H1 не означает полноценного прочтения страницы: часть страниц защищена или имеет проблемы кодировки. Решения по смешанным интентам — `selected-intent-review.json`.

## Команды

```sh
npm run seo:factory -- --dry-run
npm run seo:factory -- --dry-run --resume
npm run seo:factory -- --resume
npm run seo:audit
npm run seo:verify
npm run seo:qa
npm run seo:ledger -- --snapshot
npm run seo:report
```

`seo:qa` требует запущенный сервер 127.0.0.1:3000; альтернативный адрес — `QA_BASE_URL`. Проверяет SSR без JavaScript, схемы, CTA, интерактивную форму, события, sitemap, 404 и мобильные версии эталонов.

Dry-run пишет исследования и отчёты, но не контент. Resume использует состояние этапов и fingerprint входов; изменённые входы запускают этапы заново. `--force-refresh` обновляет API-данные и может расходовать квоту. Ошибки 429/5xx повторяются с задержкой, запросы ограничены по скорости, частичные результаты сохраняются.

Секреты `WORDSTAT_API_KEY` и `YANDEX_FOLDER_ID` передаются через окружение. Настоящие ключи, сырые ответы, API-кеш, ZIP и локальные исходники устройств исключены из Git. Для повторного запуска имеющейся партии достаточно кеша; на новом компьютере для сбора нужны ключи.

## Следующая партия

1. Проверить top opportunities, актуальные SERP и первичные источники. Уточнить интент и объединить конкурирующие темы.
2. Подготовить JSON массива по образцу `seo/data/golden-content.json`: метаданные, источники, прямой ответ, визуальный пример, оригинальный body. Генератор принимает уже написанный материал, не выдаёт API-заготовки за авторские статьи.
3. `npm run seo:factory -- --source=path/to/batch.json`. Будут созданы briefs и draft-файлы; существующие страницы не перезаписываются по умолчанию.
4. Проверить каждый текст, источники, CTA, перелинковку и визуальные примеры. Выставить `status: noindex` для браузерного preview. `prepare-release.mjs` содержит редакционные группы первой партии; не применять их механически к новым темам.
5. Запустить audit, локальную визуальную/SSR-проверку, затем явно подписать выбранные страницы: `npm run seo:audit -- --approve --slugs=first-slug,second-slug`. Связанные страницы должны быть опубликованы или подписываться вместе.
6. После изменения подписанного контента вернуть его в `noindex`, сбросить review и повторить проверку. Хеш включает текст и содержательные метаданные; старая подпись не подходит изменённой странице.
7. Build → QA → commit/deploy → ledger snapshot. Автоматической массовой публикации нет.

## Архитектура и масштаб

`content/guides/*.json + *.mdx` — безопасный ограниченный формат; произвольный JSX/HTML не исполняется. `lib/guides.ts` читает/кеширует коллекцию, проверяет подписи и отбирает публикации. Страницы серверные и статические. Список пагинирован; sitemap разбивается по 500 статей. Draft не получает доступного маршрута, noindex-preview исключён из sitemap, approved — включён.

Проверки: уникальность title/description/H1/canonical/query/intent ID, минимальный содержательный объём, источники, provenance, related links, 5-граммная близость и полные дубликаты. 5000 синтетических документов проверены алгоритмом similarity примерно за 1.5 секунды. Это не тест полной сборки 5000 страниц: перед таким расширением отдельно измерить память и время SSG и разбить редакционные партии.

## Измерение результата

`seo/data/experiment-ledger.jsonl` — append-only события с idempotent ID; повторный snapshot не дублирует запись. Baseline сейчас NULL: настоящей аналитики ещё нет. `--import=path/to/measurements.json` принимает реальные измерения с source (`gsc`, `yandex-webmaster`, `analytics`, `manual`), slug, measuredAt, impressions/clicks/ctr/averagePosition/indexationStatus/ctaClicks/caseClicks/contacts/daysSincePublication. CTR задаётся 0..1.

Правила 30/60/90 дней в `checks.mjs` — эвристики, не доказательство причинности. Дата фактического деплоя должна быть зафиксирована отдельно от готовности в репозитории. Не использовать дату подготовки как доказательство нахождения в индексе.

Клиент отправляет шесть событий `imanakov:analytics` и, если уже настроен, `dataLayer`: page view, CTA view/click, contact click, case click, related page click. В payload есть slug, clusterId, intent, topic, keyword и CTA placement/type. Внешний счётчик не подключён. Mailto переносит контекст страницы, но реальную отправку письма нельзя считать подтверждённой по клику.
